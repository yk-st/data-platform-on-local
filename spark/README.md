
# Apache Spark

Apache Spark は、大規模データを分散処理するためのデータ処理エンジンです。
バッチ処理、SQL による集計、ストリーミング処理、機械学習などを 1 つの基盤で扱えるため、データ分析基盤やデータパイプラインで広く利用されています。

本リポジトリでは、主にデータの取り込み、変換、集計、Iceberg テーブルへの書き込みを担う実行基盤として Spark を利用しています。
ローカル環境であっても、実運用に近い形で分散処理の考え方やジョブ実行の流れを確認できるようにしています。

Apache Sparkの特徴をいくつか紹介します。

#### マスターとワーカー
- **マスター**（Cluster Manager）がクラスタ全体の CPU・メモリを管理し、アプリ（Driver）へ割り当て  
- **ワーカー**はマスターに登録し、Executor 用スロットを提供  
- **スケールアウト**：ワーカー台数を増やすだけで並列度を拡張  
- **フェイルオーバ**：ワーカー障害時は別ノードへタスクを再配置  

#### ExecutorとDriver
- **Driver**  
  - アプリ起動点。DAG 生成・最適化・タスクスケジューリングを担当  
  - 進捗・障害を監視し、結果をユーザに返す  
- **Executor**  
  - ワーカー内で起動。タスク実行・シャッフル・キャッシュを担う  
  - アプリ単位のライフサイクルで中間データをプロセス内共有  
- **協調動作**：Driver ⇄ Executor RPC でタスク配布・結果集約し、高スループットを実現  

#### 遅延実行（Lazy Evaluation）
- **計算を後ろ倒し**し、`map` や `filter` は DAG に蓄積 → `action` 実行時にまとめて計算  
事前に全工程を把握できるため、フィルタの前倒しや列プルーニングなどのクエリ最適化を一括で適用でき、I/Oとシャッフルを最小化します。
Driverはクラスタ状況（空きリソース、データ局所性）を見て物理実行計画を動的に組み換えられ、スケールアウトしやすい

- **最適化**：列プルーニングやフィルタ前倒しで I/O & シャッフルを最小化  
- **メモリ効率**：必要になるまで中間データを生成しない  
- **部分再計算**：失敗ステージだけをリトライできる  
- **早期バリデーション**：実行前にスキーマ整合性をチェック  


Application（アプリ） … Driver プロセス全体

Job … Action（write、count など）を打つたびに発火

Stage … Shuffle 境界で区切られた処理の塊

Task … 最小単位。各 パーティションを1つ担当して Executor の1コアで走るスレッド

# 初期設定

事前にDockerイメージを作成し、imageをDockerHubへPushしています。
詳細は、[artifact_base](../artifact_base/README.md)を参照してください。

## get_spark()

Spark Sessionを作成するUtilです。

### 何も指定しなければ デフォルトのクラスタspark://spark-master1.local.data.platform:7077へ接続します。
spark = get_spark(app_name="train-model")

### master を一時的にローカルへ切替え
spark_local = get_spark(app_name="debug",
                        master="local[*]",
                        extra_conf={"spark.sql.shuffle.partitions": "50"})

Replは起動時のSparkインスタンスをそのまま利用します。
